## 5. Mandatory Stage 4 implementation sequence

When coding begins after successful §4.3 verification, preserve this **mandatory per-attempt** sequence (outside the write transaction):

1. Establish trusted Connection binding and same-Connection identity.
2. Obtain fresh Vault metadata through the accepted VMP-1 port/seam (`lookupExact` / `lookupVaultMetadataForConnection`), including blank-ID pre-Port validation.
3. Resolve typed occupancy through the module-local D-path helper (**OQ-S4-03 Option A**) as `FivConn04LiveSlotOccupancy`.
4. Re-invoke `classifyFivConn04LiveConnection` with complete current trusted inputs (trusted Connection + fresh Vault meta + occupancy).
5. Only then proceed through existing B-04 write-authority controls (`proveWriteAuthority` / `assertWriteAuthorityInTransaction` → `Conn04MigrationBoundaryService.assertWriteAuthority`).

### 5.1 Fail-closed semantics (binding)

| Class | Required behavior |
| --- | --- |
| Blank-ID pre-Port validation | Fail closed **before** Port/repository metadata I/O; **zero** Port calls; **zero** repository metadata calls |
| Port `NOT_FOUND` | Fresh Vault lookup returns `NOT_FOUND`; attempt fails closed / skipped; **do not** run occupancy; **do not** run C; no eligible B-04 proof; no env UPDATE. **Not** a C classification result |
| Port `INVALID` | Fail closed; **do not** claim blank-ID-style universal zero-I/O; no occupancy/C/B-04 eligible progression |
| Port `UNAVAILABLE` | Systemic fail-closed / batch-abort class; no UPDATE |
| Occupancy `occupied` | Attempt skip/fail-closed; no UPDATE |
| Occupancy `unavailable` | **Never** treated as vacant; batch-abort class; no UPDATE |
| C non-eligible after reclassification | Occurs **after** successful Vault + occupancy and C re-invoke; stop **before** eligible B-04 proof; no UPDATE |
| B-04 write-authority failure | Stop subsequent attempts; no UPDATE; **no** lease/fence/CAS bypass |
| Nest DI | **Not** authorization |
| A Preflight / `ELIGIBLE_LIVE` | Informational only; **not** write authority |
